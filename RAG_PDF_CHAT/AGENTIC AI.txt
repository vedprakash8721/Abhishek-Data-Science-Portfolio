1. INTRODUCTION TO AGENTIC 
ARTIFICIAL INTELLIGENCE 
Artificial Intelligence has evolved from traditional rule-based systems into sophisticated systems 
capable of understanding natural language, generating content, analyzing information, and 
performing complex operations. 
Traditional AI systems were generally designed to perform specific tasks. They received input, 
processed it using predefined algorithms or trained models, and generated an output. 
For example, a traditional spam detection system analyzes an email and determines whether it 
is spam or legitimate. A traditional recommendation system analyzes user behavior and 
recommends products. 
Generative Artificial Intelligence introduced another level of capability by allowing machines to 
generate new content, including text, images, audio, video, and computer code. 
Large Language Models (LLMs) such as GPT, Llama, Claude, Gemini, and Qwen made it 
possible to build systems that understand natural-language instructions and generate 
human-like responses. 
However, generating an answer is not sufficient for every real-world problem. Many tasks 
require multiple operations, interaction with external systems, decision-making, and continuous 
evaluation. 
For example, consider a user requesting: 
"Analyze all the PDF documents in my company folder, identify the important information about 
employee policies, compare the policies, and prepare a detailed report." 
A basic LLM can explain employee policies if the relevant information is provided in its context. 
However, completing the entire task requires several additional capabilities: 
-------2--------1.​ Accessing the company folder. 
2.​ Identifying available PDF documents. 
3.​ Reading and extracting document content. 
4.​ Understanding the user's requirements. 
5.​ Retrieving relevant information. 
6.​ Comparing information from multiple documents. 
7.​ Identifying inconsistencies. 
8.​ Organizing the findings. 
9.​ Generating a final report. 
10.​Verifying whether the report addresses the original request. 
An Agentic AI system can coordinate these operations through an organized workflow. 
This is the primary motivation behind Agentic AI. 
2. DEFINITION OF AGENTIC AI 
Agentic AI is an approach to designing artificial intelligence systems that can pursue specified 
objectives by interpreting instructions, planning actions, selecting appropriate tools, executing 
operations, observing results, and adapting their behavior based on feedback. 
The term "agentic" originates from the concept of agency, which refers to the ability of an entity 
to act toward achieving a particular objective. 
In the context of artificial intelligence, agency describes the ability of an AI system to perform 
goal-oriented actions rather than simply generating responses to individual inputs. 
An Agentic AI system typically combines several technologies: 
●​ Large Language Models. 
●​ Natural Language Processing. 
●​ Planning algorithms. 
●​ Reasoning mechanisms. 
●​ External tools and APIs. 
●​ Memory systems. 
●​ Knowledge retrieval systems. 
●​ Workflow orchestration. 
●​ Monitoring and evaluation mechanisms. 
Agentic AI is not a single model or programming library. It is an architectural approach that 
combines different components to develop intelligent systems capable of completing multi-step 
tasks. 
-------3--------A system can be considered agentic when it demonstrates meaningful goal-directed behavior, 
selects or adapts actions based on intermediate results, and operates within a defined 
environment and set of constraints. 
2.1 Fundamental Difference Between Generative AI and 
Agentic AI 
Generative AI primarily focuses on producing new content based on input instructions. 
Agentic AI focuses on achieving an objective through a sequence of decisions and actions. 
Consider the following example. 
User instruction: 
"Find information about Python programming and create a beginner learning plan." 
A generative AI system may directly generate a learning plan using its existing knowledge. 
An Agentic AI system may: 
●​ Understand the requested learning objective. 
●​ Search educational resources. 
●​ Retrieve relevant information. 
●​ Compare learning materials. 
●​ Identify important topics. 
●​ Organize them according to difficulty. 
●​ Create a structured learning plan. 
●​ Evaluate whether all requested requirements are satisfied. 
The difference is that the agentic system can interact with external tools and make intermediate 
decisions to complete the task. 
However, an agentic workflow does not always require unrestricted autonomy. It may contain 
predefined stages, approval points, and deterministic execution logic. 
3. FUNDAMENTAL CONCEPTS OF 
AGENTIC AI 
Understanding the fundamental concepts is necessary before implementing an Agentic AI 
application. 
-------4--------3.1 Autonomy 
Autonomy refers to the ability of an AI system to perform operations without requiring 
continuous human instructions. 
In a conventional chatbot, the user generally provides an instruction for each interaction. 
In an agentic workflow, the user can provide a high-level objective, and the system can 
determine the intermediate steps required to achieve it. 
For example: 
User objective: 
"Research the latest developments in artificial intelligence and prepare a summary." 
The system may independently perform searching, document retrieval, summarization, and 
report preparation. 
Autonomy should always operate within predefined permissions and limitations. 
An agent should not automatically receive unrestricted access to files, databases, financial 
systems, or external applications. 
3.2 Goal-Oriented Behavior 
An agentic system operates toward a defined goal. 
A goal represents the desired final result of an operation. 
Examples include: 
●​ Answering a technical question. 
●​ Preparing a research report. 
●​ Analyzing a collection of documents. 
●​ Extracting information from PDFs. 
●​ Finding relevant database records. 
●​ Completing a software development task. 
A properly defined goal should include the expected result, constraints, and completion 
conditions. 
3.3 Reasoning 
-------5--------Reasoning is the process of evaluating available information and determining an appropriate 
next action. 
An LLM can perform language-based reasoning by processing instructions, context, and 
intermediate results. 
For example, an AI research assistant may determine that the initial search results do not 
contain enough information and decide to search another source. 
Reasoning does not guarantee correctness. Language models can produce incorrect 
conclusions, misunderstand requirements, or select inappropriate actions. 
Therefore, reasoning should be combined with verification and controlled execution. 
3.4 Planning 
Planning is the process of breaking a complex objective into smaller operations. 
For example, consider the objective: 
"Build a RAG application for company PDF documents." 
An agentic planning process might divide this objective into: 
1.​ Identify the PDF files. 
2.​ Load the documents. 
3.​ Extract text. 
4.​ Clean extracted text. 
5.​ Divide text into chunks. 
6.​ Generate embeddings. 
7.​ Store embeddings in a vector database. 
8.​ Accept user questions. 
9.​ Retrieve relevant chunks. 
10.​Generate answers using an LLM. 
11.​Evaluate answer quality. 
Planning makes complex tasks easier to manage and execute. 
3.5 Tool Usage 
Tool usage allows an AI agent to interact with external software systems. 
A language model cannot automatically access every database, website, or computer 
application. 
-------6--------The application developer must provide tools that allow the model to interact with those 
systems. 
Examples include: 
●​ Web search tools. 
●​ Python execution tools. 
●​ Database query functions. 
●​ File reading tools. 
●​ PDF extraction tools. 
●​ Email APIs. 
●​ Weather APIs. 
●​ Search engines. 
●​ Vector databases. 
Tool usage is one of the most important capabilities of Agentic AI. 
3.6 Memory 
Memory allows an agentic system to retain information needed for current or future operations. 
Without memory, an agent may lose important information between different stages of a task. 
For example, a research agent may need to remember: 
●​ The user's original objective. 
●​ Which documents have already been searched. 
●​ Which information has been retrieved. 
●​ Which operations are complete. 
●​ Which operations remain. 
Memory can be divided into several categories. 
Short-Term Memory: 
Stores temporary information related to the current conversation or task. 
Long-Term Memory: 
Stores information that may be useful across multiple interactions. 
Working Memory: 
Contains information currently being used by the agent to make decisions. 
Episodic Memory: 
-------7--------Stores records of previous interactions or completed tasks. 
Semantic Memory: 
Stores structured knowledge, facts, and concepts. 
In practical applications, memory may be implemented using conversation history, databases, 
vector stores, or other storage mechanisms. 
These categories are conceptual design patterns rather than mandatory memory modules in 
every agent. 
3.7 Feedback and Adaptability 
An agentic system must be able to inspect the results of its actions. 
Suppose an agent searches a document database but receives no relevant results. 
Instead of immediately generating an unsupported answer, it may: 
1.​ Inspect the search result. 
2.​ Identify that the query may be too specific. 
3.​ Rewrite the search query. 
4.​ Perform another retrieval operation. 
5.​ Evaluate the new results. 
6.​ Decide whether sufficient evidence is available. 
This process allows the agent to adapt its behavior based on feedback. 
4. WHAT IS AN AI AGENT? 
An AI agent is a software entity that receives information from its environment, processes that 
information, selects actions, and performs operations to achieve an objective. 
An AI agent generally contains: 
1.​ Input processing. 
2.​ Goal definition. 
3.​ Reasoning or decision-making. 
4.​ Action selection. 
5.​ Tool execution. 
6.​ Environment observation. 
7.​ State management. 
-------8--------An AI agent may use an LLM as its reasoning engine, but not every AI agent requires an LLM. 
Traditional rule-based agents, robotic agents, and reinforcement-learning agents are also 
examples of AI agents. 
4.1 AI Agent Working Example 
Consider an AI customer support agent. 
The user asks: 
"Check my order status and tell me why delivery is delayed." 
The agent performs the following operations: 
First, it receives the user's request and identifies that order information is required. 
Second, it extracts the order identifier or asks the user for it if missing. 
Third, it calls an order management API. 
Fourth, it retrieves the current order status. 
Fifth, it checks delivery information using a shipping API. 
Sixth, it analyzes the retrieved information. 
Finally, it provides the user with an explanation. 
This is an example of an AI agent because the system performs multiple connected operations 
to achieve the requested objective. 
5. CORE ARCHITECTURE OF AGENTIC AI 
The architecture of an Agentic AI application defines how its different components communicate 
and work together. 
A typical architecture contains the following components. 
5.1 User Interface Layer 
The user interface is the entry point through which users interact with the agent. 
It may be: 
-------9--------●​ A web application. 
●​ A desktop application. 
●​ A mobile application. 
●​ A command-line interface. 
●​ A chatbot. 
●​ A REST API. 
The interface receives the user's request and sends it to the agent. 
Common technologies include: 
●​ Streamlit. 
●​ FastAPI. 
●​ Flask. 
●​ React. 
●​ Gradio. 
5.2 Large Language Model Layer 
The LLM acts as the language understanding and generation component. 
Its responsibilities may include: 
●​ Understanding user instructions. 
●​ Extracting important information. 
●​ Selecting tools. 
●​ Generating structured outputs. 
●​ Interpreting tool results. 
●​ Producing final responses. 
Examples of models include GPT, Llama, Gemini, Claude, and Qwen. 
5.3 Planning Layer 
The planning component determines how to accomplish the requested objective. 
For example, a document research task may require: 
●​ Identifying relevant documents. 
●​ Searching documents. 
●​ Extracting information. 
●​ Comparing results. 
●​ Preparing a report. 
Planning can be performed by an LLM, a deterministic workflow, or a combination of both. 
-------10--------5.4 Tool Layer 
The tool layer connects the agent to external functionality. 
Examples: 
A web search tool retrieves information from the internet. 
A Python tool executes code. 
A database tool retrieves records. 
A PDF reader extracts document content. 
A vector database retrieves semantically similar document chunks. 
Tools should have well-defined input parameters and output formats. 
5.5 Memory Layer 
The memory layer stores information required during execution. 
It may contain: 
●​ Conversation history. 
●​ Current task state. 
●​ Retrieved information. 
●​ Previous tool results. 
●​ User preferences, where appropriate. 
Memory should be designed with privacy, retention, and access-control requirements. 
5.6 Orchestration Layer 
Orchestration manages the sequence of operations performed by the agent. 
It controls: 
●​ Which component executes first. 
●​ Which tool should be called. 
●​ Whether an operation should be repeated. 
●​ Whether another agent should be invoked. 
●​ Whether human approval is required. 
●​ When the workflow should stop. 
-------11--------LangGraph is one framework commonly used for stateful workflow orchestration. 
5.7 Evaluation Layer 
The evaluation layer checks whether the agent has completed its objective correctly. 
For example: 
If the user requests a report containing five sections, the evaluation component can verify 
whether all five sections are present. 
Evaluation can include deterministic checks, model-based grading, human review, and external 
test cases. 
5.8 Safety and Security Layer 
This component restricts what the agent is allowed to do. 
Examples: 
●​ Preventing unauthorized database access. 
●​ Validating tool inputs. 
●​ Restricting file operations. 
●​ Preventing sensitive information disclosure. 
●​ Requiring confirmation before sending emails. 
●​ Limiting execution time and API usage. 
Security should be implemented at the application and tool layers rather than relying only on 
instructions given to the LLM. 
6. HOW AGENTIC AI WORKS: COMPLETE 
EXECUTION CYCLE 
A common conceptual execution cycle is: 
PERCEPTION → REASONING → PLANNING → ACTION → OBSERVATION → EVALUATION 
This cycle may repeat until the goal is achieved or the system reaches a stopping condition. 
6.1 Perception 
-------12--------Perception is the process of receiving and understanding information from the environment. 
The environment may provide: 
●​ User messages. 
●​ PDF documents. 
●​ Database records. 
●​ API responses. 
●​ Search results. 
●​ Images. 
●​ Audio. 
●​ Application events. 
The agent processes the available information and identifies what is relevant. 
6.2 Reasoning 
The agent evaluates the user's request and available information. 
It identifies: 
●​ What the user wants. 
●​ What information is required. 
●​ Which constraints apply. 
●​ Which tools are available. 
●​ Whether clarification is necessary. 
6.3 Planning 
The agent creates a sequence of steps. 
For example: 
Goal: Answer a question using multiple PDF files. 
Plan: 
1.​ Search the document index. 
2.​ Retrieve relevant chunks. 
3.​ Check whether the information is sufficient. 
4.​ Retrieve additional chunks if necessary. 
5.​ Generate a grounded answer. 
6.​ Include document references. 
-------13--------6.4 Action 
The agent executes an operation. 
An action may include: 
●​ Calling a search API. 
●​ Querying a database. 
●​ Reading a file. 
●​ Running Python code. 
●​ Retrieving document chunks. 
●​ Sending a request to another service. 
6.5 Observation 
The agent receives the result of its action. 
For example, a vector database may return five relevant document chunks. 
The agent examines these results and determines whether they are useful. 
6.6 Evaluation 
The agent checks whether the original objective has been satisfied. 
If sufficient information is available, it generates the final response. 
If information is missing, it may execute another retrieval operation or request clarification. 
This cycle continues under defined limits. 
7. DIFFERENT TYPES OF AI AGENTS 
AI agents can be categorized according to how they make decisions and interact with their 
environment. 
7.1 Simple Reflex Agents 
Simple reflex agents select actions using predefined condition-action rules. 
They respond to the current input without necessarily maintaining information about previous 
events. 
-------14--------Example: 
IF temperature > 30°C: 
Turn on cooling system. 
Otherwise: 
Keep cooling system off. 
Simple reflex agents are suitable for predictable environments. 
7.2 Model-Based Reflex Agents 
Model-based reflex agents maintain an internal representation of the environment. 
This helps them make decisions using both current observations and stored state. 
Example: 
A robot vacuum remembers which areas have already been cleaned. 
7.3 Goal-Based Agents 
Goal-based agents select actions according to a specific objective. 
Example: 
A navigation system identifies a destination and determines a route to reach it. 
7.4 Utility-Based Agents 
Utility-based agents evaluate possible outcomes using a utility function. 
The utility function represents preferences such as: 
●​ Lower cost. 
●​ Shorter completion time. 
●​ Higher performance. 
●​ Lower risk. 
Example: 
A travel planning agent compares different routes based on price, duration, and convenience. 
-------15--------7.5 Learning Agents 
Learning agents improve their behavior based on feedback or experience. 
They may use machine learning, reinforcement learning, or other learning techniques. 
Example: 
A recommendation system learns from user interactions to improve future recommendations. 
7.6 LLM-Based Agents 
LLM-based agents use language models to understand instructions, reason about tasks, and 
select tools. 
They are widely used in modern Agentic AI applications. 
Example: 
A document assistant that uses an LLM to decide whether to search a PDF collection or query a 
database. 
8. IMPORTANT AGENTIC AI DESIGN 
PATTERNS 
Design patterns describe reusable approaches for organizing agentic workflows. 
8.1 ReAct Pattern 
ReAct stands for Reasoning and Acting. 
It is a pattern in which a language model alternates between deciding what to do and performing 
an action. 
The general process is: 
1.​ Receive a question. 
2.​ Determine the next required operation. 
3.​ Execute a tool. 
4.​ Observe the result. 
5.​ Decide what to do next. 
-------16--------Example: 
Question: 
"What is the current population of a particular city?" 
The agent may identify that current information is required, invoke an approved search tool, 
inspect the results, and generate an answer. 
ReAct is useful when a task requires multiple interactions with external tools. 
8.2 Plan-and-Execute Pattern 
In this pattern, an agent first generates a plan and then executes the planned steps. 
Example: 
Task: Prepare a research report about RAG. 
Planning stage: 
●​ Find information about RAG architecture. 
●​ Research vector databases. 
●​ Study embedding models. 
●​ Compare retrieval methods. 
●​ Prepare a report. 
Execution stage: 
The agent performs each operation and collects the results. 
This pattern is useful for tasks with multiple clearly identifiable subtasks. 
8.3 Reflection Pattern 
Reflection involves evaluating an intermediate result and determining whether it requires 
improvement. 
Example: 
A report-writing agent generates a report. 
An evaluator checks: 
●​ Whether all requested topics are covered. 
●​ Whether the information is relevant. 
-------17--------●​ Whether references are included. 
●​ Whether the format is correct. 
If the result does not satisfy the requirements, the system may revise it. 
Reflection is not a guarantee of correctness. Independent verification is preferable for important 
claims. 
8.4 Router Pattern 
A router determines which tool or processing path should handle a request. 
Example: 
If the question is related to company policy, use the HR document retriever. 
If the question is related to programming, use the technical documentation retriever. 
If the question is related to project status, use the project database. 
This pattern is useful when an application has multiple knowledge sources. 
8.5 Multi-Agent Collaboration Pattern 
Multiple specialized agents work together on a larger objective. 
For example: 
A research system may contain: 
Research Agent: 
Collects relevant information. 
Analysis Agent: 
Examines the collected information. 
Writing Agent: 
Prepares the final report. 
Review Agent: 
Checks the report for completeness and quality. 
-------18--------The agents communicate through a coordinator or shared workflow state. 
Multi-agent systems can improve modularity, but they also increase complexity, latency, and 
operational cost. 
9. SINGLE-AGENT AND MULTI-AGENT 
SYSTEMS 
9.1 Single-Agent Architecture 
A single-agent architecture uses one primary agent to complete the task. 
The agent may have access to multiple tools. 
Example: 
An AI document assistant has: 
●​ PDF reader. 
●​ Vector search. 
●​ Python calculator. 
●​ Database query function. 
The same agent decides which tool to use. 
Advantages: 
●​ Simpler architecture. 
●​ Easier debugging. 
●​ Lower coordination overhead. 
●​ Easier state management. 
●​ Lower operational complexity. 
Disadvantages: 
●​ A single agent handles multiple responsibilities. 
●​ Complex tasks may become difficult to organize. 
●​ Tool selection may become less reliable as the available toolset grows. 
9.2 Multi-Agent Architecture 
A multi-agent architecture contains multiple agents with different responsibilities. 
-------19--------Example: 
A RAG research system may contain: 
1.​ Query Understanding Agent. 
2.​ Document Retrieval Agent. 
3.​ Data Analysis Agent. 
4.​ Answer Generation Agent. 
5.​ Evaluation Agent. 
Each agent performs a specialized operation. 
Advantages: 
●​ Separation of responsibilities. 
●​ Modular development. 
●​ Specialized processing. 
●​ Potential parallel execution. 
Disadvantages: 
●​ More complicated orchestration. 
●​ Higher computational cost. 
●​ Communication overhead. 
●​ Difficult debugging. 
●​ Possibility of conflicting agent outputs. 
A multi-agent architecture is not automatically better than a single-agent architecture. 
The architecture should be selected according to the complexity of the actual task.

●​ Building chains and workflows.

Provide a standardized interface for interacting with different conversational language models. 
Prompt Templates: 
Allow developers to create reusable prompts containing dynamic variables. 
Tools: 
Allow an LLM-powered application to call predefined functions. 
Document Loaders: 
Load documents from different sources. 
Text Splitters: 
Divide large documents into smaller chunks. 
Retrievers: 
Retrieve relevant information from a knowledge source.

Convert model responses into structured formats.
